# Azure SQL
**Date created:** 2026-07-15 UTC  
**Tags:** Administration, Other, Security  

## New Articles

- **Data integrity in Azure SQL Managed Instance**

  Introduced new end-to-end guidance on how Azure SQL maintains data integrity across Azure SQL Database and Managed Instance, including monitoring for integrity errors, detecting lost writes via page LSN checks, and automatic page repair using replicas. Clarifies checksum verification for pages, TLS in transit, and integrity checks during backup and restore, with incident response workflows that distinguish system vs. customer data issues and outline communication practices. Provides customer remediation options such as index rebuilds, DBCC CHECKDB repair modes, and point-in-time restore with manual log replay; includes Hyperscale-specific guidance to use DBCC CHECKTABLE WITH TABLOCK. Highlights optional customer-initiated integrity checks and directs readers to related backup documentation and feedback channels.

  https://learn.microsoft.com/en-us/azure/azure-sql/managed-instance/data-integrity?view=azuresql

## Moderate Changes

- **Automated backups in Azure SQL Managed Instance**

  Clarified backup integrity behavior by documenting the use of CHECKSUM and replacing prescriptive guidance about scheduling DBCC CHECKDB with broader recommendations to validate restores and run integrity checks as needed. This improves accuracy around built-in protections while guiding customers to proactively verify recoverability and data integrity.

  https://learn.microsoft.com/en-us/azure/azure-sql/managed-instance/automated-backups-overview?view=azuresql

- **Manage After Migration**

  Updated post-migration data synchronization guidance to reflect Data Sync retirement, pointing to supported migration alternatives. Emphasized Microsoft Entra integration for authentication, removed Azure Synapse references in the auth table, and added anchors and targeted clarifications across security, auditing, threat detection, networking, and integrity checks to streamline setup and operations.

  https://learn.microsoft.com/en-us/azure/azure-sql/database/manage-data-after-migrating-to-database?view=azuresql

- **Hyperscale service tier**

  Refined integrity check guidance to state that DBCC CHECKDB and DBCC CHECKFILEGROUP aren’t supported for Azure SQL Database Hyperscale, and to use only DBCC CHECKTABLE('TableName') WITH TABLOCK as the workaround. This helps teams run supported checks without relying on unsupported commands.

  https://learn.microsoft.com/en-us/azure/azure-sql/database/service-tier-hyperscale?view=azuresql

- **vCore purchasing model - Azure SQL Database**

  Removed the Business Critical tier statement about advanced corruption protection via automatic page repair and the note regarding availability in General Purpose with a geo-secondary replica. This eliminates overstated or outdated claims, aligning expectations with current capabilities.

  https://learn.microsoft.com/en-us/azure/azure-sql/database/service-tiers-sql-database-vcore?view=azuresql

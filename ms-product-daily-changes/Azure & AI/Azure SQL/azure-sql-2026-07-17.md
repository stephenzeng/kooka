# Azure SQL
**Date created:** 2026-07-17 UTC  
**Tags:** Administration, Automation, Security  

## Major Changes

- **Overview of SQL Server on Linux Azure Virtual Machines**

  Updated the getting started experience to a streamlined three-step path: provision a Linux VM, install SQL Server 2017 or later, and register with the SQL IaaS Agent extension. Shifted guidance from gallery image-based provisioning to a script-driven approach and removed distribution-specific package tables and peripheral tips. Added a note about the transition to script-based provisioning with a link to the announcement, helping readers adopt a consistent, future-ready setup flow. This refocus reduces confusion and aligns deployments with current best practices.

  https://learn.microsoft.com/en-us/azure/azure-sql/virtual-machines/linux/sql-server-on-linux-vm-what-is-iaas-overview?view=azuresql

- **Provision a Linux virtual machine running SQL Server in the Azure portal**

  Refactored the quickstart to create a generic Linux VM, then install SQL Server 2017 or later post-provisioning for greater flexibility. Introduced steps to register the VM with the SQL IaaS Agent extension to unlock management features, and removed outdated instructions like resetting the SA password. This approach aligns with modern, script-first provisioning and provides clearer operational guidance.

  https://learn.microsoft.com/en-us/azure/azure-sql/virtual-machines/linux/sql-vm-create-portal-quickstart?view=azuresql

## Moderate Changes

- **Enable Microsoft Entra authentication for SQL Server on Azure VMs**

  Expanded prerequisites and limitations to support SQL Server 2022 or later and clarified that deployments are supported across any Azure cloud. These changes broaden compatibility and make guidance clearer for multi-cloud Azure environments.

  https://learn.microsoft.com/en-us/azure/azure-sql/virtual-machines/windows/configure-azure-ad-authentication-for-sql-vm?view=azuresql

- **Deploy SQL Server to an Azure confidential VM**

  Updated guidance to reflect current confidential computing standards, including sovereign requirements and a generalized description of memory encryption. Revised supported regions, shifted VM recommendations to DC/EC adsv6-series, and refreshed the SQL Server image list to Windows Server 2025/2022 editions, removing older versions and Developer edition. This ensures deployments use supported hardware and images that meet security and compliance expectations.

  https://learn.microsoft.com/en-us/azure/azure-sql/virtual-machines/windows/sql-vm-create-confidential-vm-how-to?view=azuresql

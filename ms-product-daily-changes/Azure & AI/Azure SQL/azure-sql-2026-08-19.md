# Azure SQL
**Date created:** 2026-08-19 UTC  
**Tags:** Configuration, Governance  

## Major Changes

- **Request quota increases for Azure SQL Database and SQL Managed Instance**

  Updated the Azure portal workflow for submitting quota increase requests, including a direct link to create a support request and revised selections for service, problem type, and steps. Clarified how to specify Region and the desired quota limit in Quota details, and standardized section headers. Introduced a major change to SQL Managed Instance quota types: subnet quotas no longer apply, and vCore quotas are now scoped per hardware generation (Standard-Series, Premium-Series, Memory Optimized Premium-Series). Prior regional vCore quota increases now carry forward equally to each hardware generation in that region, simplifying planning and requests.

  https://learn.microsoft.com/en-us/azure/azure-sql/database/quota-increase-request?view=azuresql

- **Overview of Azure SQL Managed Instance resource limits**

  Removed the subnet quota concept and consolidated limits to vCore unit quotas scoped per hardware generation. Revised the limits table, notes, and IMPORTANT callouts to reflect that only vCore limits apply, including details per subscription type and regions with higher limits. Added a note that starting August 2026, subnet quotas no longer apply and vCore quotas are per hardware generation, with a link to the quota request types section.

  https://learn.microsoft.com/en-us/azure/azure-sql/managed-instance/resource-limits?view=azuresql

## Moderate Changes

- **What's new in Azure SQL Managed Instance?**

  Added a new entry describing updated quota request types: subnet quotas no longer apply, and vCore quotas are now scoped per hardware generation. This highlights how existing regional vCore allowances carry forward by hardware generation, helping customers plan capacity.

  https://learn.microsoft.com/en-us/azure/azure-sql/managed-instance/doc-changes-updates-release-notes-whats-new?view=azuresql

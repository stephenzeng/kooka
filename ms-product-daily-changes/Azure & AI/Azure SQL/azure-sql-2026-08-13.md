# Azure SQL
**Date created:** 2026-08-13 UTC  
**Tags:** Configuration, Guidance, Licensing, Troubleshooting  

## Moderate Changes

- **Known issues with Azure SQL Managed Instance**

  Added a known issue for change event streaming where the committime field incorrectly appends a Z suffix on non-UTC systems. Clarified impact, updated the issues table, and noted that a fix is pending with no current workaround so users can interpret timestamps accurately.

  https://learn.microsoft.com/en-us/azure/azure-sql/managed-instance/doc-changes-updates-known-issues?view=azuresql

- **Create an instance pool - Azure SQL Managed Instance**

  Updated licensing guidance for Managed Instance pools, requiring manual activation of Azure Hybrid Benefit and removing references to hybrid failover rights. Clarified unsupported features: license-free DR replicas (including failover rights and hybrid failover rights) are not available in pools, and failover groups are not supported—helping customers plan DR and licensing correctly.

  https://learn.microsoft.com/en-us/azure/azure-sql/managed-instance/instance-pools-configure?view=azuresql

- **Disaster recovery with Managed Instance link - Azure SQL Managed Instance**

  Clarified that the Hybrid failover benefit only applies to passive secondary instances in SQL Server–Managed Instance hybrid scenarios and does not apply to instance pools. Added support details for SQL Server 2025 and the update policy and stated that after failing over to Managed Instance under the Always-up-to-date policy, replication and failback to SQL Server 2022/2025 aren’t possible—informing failover planning and version strategy.

  https://learn.microsoft.com/en-us/azure/azure-sql/managed-instance/managed-instance-link-disaster-recovery?view=azuresql

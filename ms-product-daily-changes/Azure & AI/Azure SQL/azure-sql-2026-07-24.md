# Azure SQL
**Date created:** 2026-07-24 UTC  
**Tags:** Administration, Monitoring, Security  

## Major Changes

- **Manage file space for databases in Azure SQL Database**

  Comprehensive rewrite and expansion of file space management guidance. Clarified when shrinking is appropriate (for elastic pools, size tier changes, and Hyperscale cost control) and cautioned against routine shrinking. Expanded monitoring recommendations using Azure metrics and system views, and consolidated examples to report used, allocated, and maximum size. Detailed shrink techniques and trade-offs (DBCC SHRINKDATABASE vs. DBCC SHRINKFILE, TRUNCATEONLY caveats, and parallel shrinks), with added guidance for transaction log behavior in Premium/Business Critical and auto-shrink behavior (ignored by Hyperscale). Introduced best practices for large shrink operations, robust transient error handling with retry patterns and specific diagnostics, a reference to the ShrinkDriver automation tool, and refined post-shrink index maintenance advice.

  https://learn.microsoft.com/en-us/azure/azure-sql/database/file-space-manage?view=azuresql-db

## Moderate Changes

- **Data integrity in Azure SQL Database**

  Updated guidance on customer-initiated integrity checks to explain how Microsoft-managed protections detect and repair issues and how DBCC CHECKDB complements them with comprehensive corruption detection. Added recommendations on performance impact and scheduling to minimize workload disruption, and clarified that Hyperscale does not support DBCC CHECKDB with DBCC CHECKTABLE WITH TABLOCK advised per table as an alternative.

  https://learn.microsoft.com/en-us/azure/azure-sql/database/data-integrity?view=azuresql

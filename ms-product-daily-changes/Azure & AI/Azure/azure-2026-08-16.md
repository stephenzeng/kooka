# Azure
**Date created:** 2026-08-16 UTC  
**Tags:** Automation, Best Practices, Billing, Configuration, Governance, Guidance, Performance, Security, Troubleshooting  

## Major Changes

- **Azure Accelerated Networking overview**

  Updated supported OS matrices, replacing lists with clear Windows and Linux/FreeBSD compatibility tables that include minimum kernel versions by distribution. Added explicit guidance that listed kernel versions represent minimum recommendations for MANA support and refined notes about ongoing feature updates with Linux vendors. This improves planning, validation, and compliance for deployments using Accelerated Networking.

  https://learn.microsoft.com/en-us/azure/virtual-network/accelerated-networking-overview

## Moderate Changes

- **Linux VMs with the Microsoft Azure Network Adapter**

  Added a detailed matrix of endorsed Linux distributions and minimum recommended kernel versions for MANA-enabled SKUs. This clarifies OS support and kernel requirements so you can validate compatibility before enabling Accelerated Networking on Linux.

  https://learn.microsoft.com/en-us/azure/virtual-network/accelerated-networking-mana-linux

- **Deploy Azure File Sync**

  Introduced deployment guidance for installing the Azure File Sync agent via the Azure File Sync Agent for Windows extension on Azure Arc–enabled servers, with steps for portal, PowerShell, and Azure CLI. The extension is Windows-only and includes configuration for auto-update, diagnostics, Microsoft Update, and proxies, followed by registering the server with a Storage Sync Service.

  https://learn.microsoft.com/en-us/azure/storage/file-sync/file-sync-deployment-guide

- **Restore an existing dedicated SQL pool**

  Updated troubleshooting for ValidationFailed errors to require sourceDatabaseId use supported resource ID formats. Added the accepted formats for Synapse SQL pool and Managed SQL Database resource IDs to prevent restore failures.

  https://learn.microsoft.com/en-us/azure/synapse-analytics/backuprestore/restore-sql-pool

- **Restore a dedicated SQL pool from a deleted workspace**

  Revised error guidance to ensure sourceDatabaseId uses supported resource ID formats, with examples for Synapse dedicated SQL pools and Azure SQL Managed databases. This reduces restore failures caused by incorrect resource IDs.

  https://learn.microsoft.com/en-us/azure/synapse-analytics/backuprestore/restore-sql-pool-from-deleted-workspace

- **Manage storage account access keys**

  Clarified key naming (key1/primary and key2/secondary) across portal, PowerShell, and CLI, and added tables mapping required RBAC actions and built-in roles for listing and rotating keys. Included explicit post-rotation verification steps and improved CLI guidance (for example, using --query) to confirm policy application and key validity.

  https://learn.microsoft.com/en-us/azure/storage/common/storage-account-keys-manage

- **Upgrade to a general-purpose v2 storage account**

  Expanded upgrade guidance to emphasize that GPv2 retains all GPv1 capabilities, detail GPv1 retirement and automatic migration considerations, and refine billing impact explanations. PowerShell and CLI sections now include parameter descriptions to help plan upgrades and estimate potential cost changes.

  https://learn.microsoft.com/en-us/azure/storage/common/storage-account-upgrade

- **What is the service catalog?**

  Added guidance for creating Azure Enclave service catalog templates using ARM JSON with secure defaults, policy compliance, validation steps, and comprehensive documentation. Included instructions for requesting new templates through feedback or support to streamline adoption.

  https://learn.microsoft.com/en-us/azure/enclave/what-service-catalog

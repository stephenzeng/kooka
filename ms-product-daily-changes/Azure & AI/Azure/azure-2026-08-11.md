# Azure
**Date created:** 2026-08-11 UTC  
**Tags:** Best Practices, Configuration, Governance, Guidance, Performance, Security, Troubleshooting  

## Major Changes

- **How to upgrade SAP-HANA and SAP-APPS PAYG virtual machines from RHEL 8.x to RHEL 9.x using Leapp**

  Consolidated the upgrade guidance to exclusively target RHEL 9.6, removing all RHEL 9.4 paths and examples. The supported upgrade matrix now lists only RHEL 9.6 for SAP HANA and SAP NetWeaver/SAP Applications. Preparation, pre-upgrade, upgrade steps, and verification instructions were updated to reflect the RHEL 9.6-only guidance.

  https://learn.microsoft.com/en-us/troubleshoot/azure/virtual-machines/linux/leapp-upgrade-rhel-8dotx-to-9dotx-saphana-sapapps

## Moderate Changes

- **Tutorial 1-4: Create Azure resources from the service catalog in an Azure Enclave workload**

  Expanded networking setup by adding explicit inputs for the Virtual Network resource group and Virtual Network names, and clarified the App Service subnet delegation requirement. These updates improve deployment accuracy and reduce configuration errors; other edits were cosmetic.

  https://learn.microsoft.com/en-us/azure/enclave/1-4-use-service-catalog-create-azure-resources-workloads

- **Choose VM sizes and images for pools**

  Clarified how Azure Batch image verification works and that an image’s verificationType can change, including transitions from verified to unverified as images near or reach end of support. Advised regularly refreshing verificationType and batchSupportEndOfLife values and noted that unverified doesn’t mean the image is nonfunctional.

  https://learn.microsoft.com/en-us/azure/batch/batch-pool-vm-sizes

- **Best practices**

  Added guidance on monitoring VM image verification status in Azure Batch, explaining verificationType behavior and potential changes over time. Recommends periodically rechecking verification values for images used by pools to avoid surprises.

  https://learn.microsoft.com/en-us/azure/batch/best-practices

- **Resource functions for Bicep**

  Clarified that extensionResourceId requires a fully qualified resource ID for the target and may fail when deploying tenant-level resources from lower scopes if not used correctly. Reiterates using symbolic names and the resource id property where possible.

  https://learn.microsoft.com/en-us/azure/azure-resource-manager/bicep/bicep-functions-resource

- **Deploy resources to management group**

  Strengthened management-group deployment guidance: use fully qualified management group resource IDs and construct them with tenantResourceId(), and ensure extensionResourceId() receives the fully qualified ID as its first argument. Recommends using symbolic names and the id property for Azure Policy definitions in Bicep to avoid scoping errors.

  https://learn.microsoft.com/en-us/azure/azure-resource-manager/templates/deploy-to-management-group

- **Deploy resources to tenant**

  Clarified that targeting a management group within a tenant requires the fully qualified resource ID and showed how to build it using tenantResourceId('Microsoft.Management/managementGroups', <name>). Updated examples replace manual concatenation with tenantResourceId for reliability and consistency.

  https://learn.microsoft.com/en-us/azure/azure-resource-manager/templates/deploy-to-tenant

- **How to create a supercomputer and nodepools in Microsoft Discovery**

  Added networking guidance for User Defined Networking, including setting outboundType and requiring a Management Subnet when enabled. Introduced an Encryption section describing how to enable customer-managed keys for data at rest, with steps and references.

  https://learn.microsoft.com/en-us/azure/microsoft-discovery/how-to-manage-supercomputers

- **Common questions about Hyper-V to Azure disaster recovery**

  Added an FAQ clarifying that On-demand Capacity Reservation is supported only for Azure-to-Azure DR scenarios and not for Hyper-V to Azure. This sets correct expectations for capacity planning.

  https://learn.microsoft.com/en-us/azure/site-recovery/hyper-v-azure-common-questions

- **About ExpressRoute Metro**

  Updated the Brussels Metro capability to reflect that it is now available, aligning the comparison table with current service availability.

  https://learn.microsoft.com/en-us/azure/expressroute/metro

- **Azure Migrate appliance**

  Refreshed appliance download details: adjusted VMware OVA size to 12.8 GB and updated its SHA256, and reduced the Windows ZIP size to 746 MB with a new checksum. These changes ensure accurate sizing and integrity verification for current builds.

  https://learn.microsoft.com/en-us/azure/migrate/migrate-appliance?view=migrate

- **NAT gateway resource**

  Clarified that the 100 Gbps limit for StandardV2 NAT gateway is total throughput per resource and introduced a new limit of up to 10 million PPS per resource. This helps with capacity planning and performance expectations.

  https://learn.microsoft.com/en-us/azure/nat-gateway/nat-gateway-resource

- **Azure SRE Agent network integration (preview)**

  Removed a documented limitation regarding kubectl operations against private AKS API servers via VNet integration, including related caveats about timeouts and output limits. This simplifies guidance and removes recommendations that are no longer applicable.

  https://learn.microsoft.com/en-us/azure/sre-agent/network-integration

- **OS and runtime patching**

  Introduced Platform Release Channels for Linux App Service, enabling control over the timing of runtime patch updates via Latest, Standard, and Extended channels. Added configuration steps in the Azure portal and an example of version progression to guide adoption.

  https://learn.microsoft.com/en-us/azure/app-service/overview-patch-os-runtime

- **Azure Private Endpoint private DNS zone values**

  Added a footnote for Foundry Tools private endpoints clarifying the mapping between public endpoint suffixes and corresponding private DNS zones. Highlights that a Foundry resource can expose multiple endpoints and that DNS must be configured for each used endpoint.

  https://learn.microsoft.com/en-us/azure/private-link/private-endpoint-dns

- **Release notes 2026: Azure Health Data Services**

  Added August 2026 updates for the FHIR service, including narrative content security enhancements to mitigate potential XSS risks. Also fixed a bulk delete date filtering issue that could delete data outside the intended range.

  https://learn.microsoft.com/en-us/azure/healthcare-apis/release-notes-2026

- **Template functions in scoped deployments**

  Clarified that extensionResourceId at management-group scope must use a fully qualified management group resource ID, and updated examples to build it with tenantResourceId(). This reduces scope-resolution errors in policy deployments.

  https://learn.microsoft.com/en-us/azure/azure-resource-manager/templates/scope-functions

- **Blob Storage feature support in Azure Storage accounts**

  Updated the matrix to mark Customer-managed (unplanned) failover as supported. This signals expanded resilience options for customers.

  https://learn.microsoft.com/en-us/azure/storage/blobs/storage-feature-support-in-storage-accounts

- **Support matrix for moving Azure VMs to another region with Azure Resource Mover**

  Added support for Ubuntu 20.04 LTS, 22.04 LTS, and 24.04 LTS (all minor versions), with references to supported kernel versions. Broadens OS coverage for VM moves across regions.

  https://learn.microsoft.com/en-us/azure/resource-mover/support-matrix-move-region-azure-vm

- **Template functions - resources**

  Clarified that extensionResourceId must receive the fully qualified resource ID of the target resource as its first argument. Updated parameter descriptions to explicitly state “fully qualified resource ID,” reducing deployment failures across scopes.

  https://learn.microsoft.com/en-us/azure/azure-resource-manager/templates/template-functions-resource

- **Troubleshoot Azure Load Balancer resource health and inbound availability problems**

  Added troubleshooting steps for asymmetric routing that diverts return traffic via a BGP-learned default route (for example, from ExpressRoute or VPN), causing timeouts. Provides a method to review effective routes and apply a UDR to restore internet egress for the backend subnet while maintaining forced tunneling elsewhere, plus validation steps to confirm recovery.

  https://learn.microsoft.com/en-us/troubleshoot/azure/load-balancer/troubleshoot-rhc

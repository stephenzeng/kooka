## New Articles

- **Automate Microsoft Foundry Agents with Workflows**

  Introduced a preview how-to for running Microsoft Foundry agents in Azure Logic Apps, explaining the agentic stack, triggers, and how workflows and connectors can act as agent tools, including long-running and human-in-the-loop scenarios. The guide provides prerequisites and step-by-step setup to create or select an agent, configure model/project connections, and add user instructions and connector actions. Follow-up updates expanded production-focused guidance, clarified agent selection/editing behavior, and added a structured connection properties table with illustrative screenshots to simplify configuration and onboarding.

  https://learn.microsoft.com/en-us/azure/logic-apps/automate-foundry-agents-with-workflows

- **Preview deployment stack changes with what-if**

  Added guidance for using what-if with Azure deployment stacks to preview and persist change results as a Microsoft.Resources/deploymentStacksWhatIfResults resource. It explains differences from standard what-if, how to reduce noise via baselines, and how unmanaged resources are reported per actionOnUnmanage. The article includes Azure CLI/PowerShell commands to create, list, retrieve (including property-level diffs), and delete results across scopes, plus recommendations for interactive confirmation and CI/CD gating with retention considerations.

  https://learn.microsoft.com/en-us/azure/azure-resource-manager/bicep/deployment-stacks-what-if

- **Change Container Apps logging from Log Analytics to Azure Monitor**

  Introduced a comprehensive migration guide for Azure Container Apps to move logging from Log Analytics (HTTP Data Collector API) to Azure Monitor resource-specific tables. It covers prerequisites and limitations, portal/CLI steps to switch destinations and configure diagnostic settings, and validation with canary markers and Kusto queries. The guide details schema changes, how to update queries/alerts/workbooks, options to build compatibility functions spanning old and new logs, rollback steps, and cost and activation delay considerations.

  https://learn.microsoft.com/en-us/azure/container-apps/migrate-logs-azure-monitor

## Major Changes

- **Configure Durable Functions App With Managed Identity**

  Expanded the quickstart to support identity-based connections for both Durable Task Scheduler and Azure Storage providers via pivots. Added a full path for Durable Task Scheduler with local development options, configuration through DTS_CONNECTION_STRING and TASKHUB_NAME, role assignment using Durable Task Data Contributor, managed identity setup (system/user-assigned), and verification steps. The Azure Storage path remains available under its own pivot, and a new Next steps link points to the Durable Task Scheduler overview to guide architecture choices.

  https://learn.microsoft.com/en-us/azure/durable-task/durable-functions/durable-functions-configure-managed-identity

- **Data persistence and serialization in Durable Functions for Azure Functions**

  Overhauled guidance to recommend Durable Task Scheduler as the preferred managed backend, positioning Azure Storage and other BYO providers for specific scenarios. Added a provider comparison table, detailed large payload support for the Scheduler (with JSON configuration), and a separate claim-check approach for Azure Storage. Security guidance now clarifies shared responsibilities and strengthens best practices for identity-based connections, RBAC, network controls, monitoring, and credential hygiene, with updated language for .NET isolated serializers and a new PowerShell tab.

  https://learn.microsoft.com/en-us/azure/durable-task/durable-functions/durable-functions-serialization-and-persistence

## Moderate Changes

- **Configure granular billing in Azure Backup (preview)**

  Updated tag-level guidance to clarify how costs roll up in Cost Management and introduced the built-in ms-resource-parent tag to consolidate backup charges. Added instructions for using a custom cm-resource-parent tag with the target resource’s ARM ID to attribute costs for chargeback and reporting.

  https://learn.microsoft.com/en-us/azure/backup/backup-azure-granular-billing

- **Azure Guest OS**

  Added a July 2026 Guest OS section listing MSRC updates for families 5.120, 6.96, and 7.66, including LCUs, .NET Framework rollups, microcode, SSU, and servicing stack updates with KB references and dates. Included links and anchors to the Guest OS update matrix for easier cross-referencing.

  https://learn.microsoft.com/en-us/azure/cloud-services-extended-support/cloud-services-guestos-microsoft-security-response-center-releases

- **Azure Guest OS releases and SDK compatibility matrix**

  Announced the July 2026 Guest OS release and added versions WA-GUEST-OS-7.66_202607-01, 6.96_202607-01, and 5.120_202607-01 with release dates and disable markers. Marked prior versions as disabled with explicit disable dates to guide upgrade planning.

  https://learn.microsoft.com/en-us/azure/cloud-services-extended-support/cloud-services-guestos-update-matrix

- **Azure Storage provider for Durable Functions**

  Clarified that Azure Storage is not the default provider and revised the introduction to recommend considering it rather than asserting default status. Updated configuration guidance to remove the default claim while retaining host.json references and the note that explicit configuration or extra packages are not required.

  https://learn.microsoft.com/en-us/azure/durable-task/durable-functions/durable-functions-azure-storage-provider

- **Diagnose and troubleshoot issues in Durable Functions**

  Added cross-provider troubleshooting with an emphasis on the recommended Durable Task Scheduler backend, pointing to the scheduler dashboard, Application Insights, and the Azure portal. Clarified logging categories for production (backend-specific plus DurableTask.Core) and generalized guidance on custom status size limits across metadata stores, prioritizing scheduler tools over storage-specific inspection.

  https://learn.microsoft.com/en-us/azure/durable-task/durable-functions/durable-functions-diagnostics

- **Upgrade the Durable Functions extension version**

  Updated upgrade guidance to include Durable Task Scheduler (recommended) with Microsoft.DurableTask.Client.Grpc for in-process and isolated workers. Retained Azure Storage, Netherite, and MSSQL providers, and removed references to Azure Storage as the default provider.

  https://learn.microsoft.com/en-us/azure/durable-task/durable-functions/durable-functions-extension-upgrade

- **Performance and scale in Durable Functions**

  Expanded performance guidance to cover Durable Task Scheduler alongside BYO providers, adding scheduler-specific caching/partitioning details managed by the service. Clarified provider-specific features, reorganized sections, and linked to action throughput benchmarks for the Scheduler.

  https://learn.microsoft.com/en-us/azure/durable-task/durable-functions/durable-functions-perf-and-scale

- **Durable orchestrations**

  Replaced storage-default language with provider-agnostic guidance and recommended Durable Task Scheduler as the managed option. Expanded consistency notes with links to eventual consistency patterns and CQRS, and clarified MSSQL provider characteristics.

  https://learn.microsoft.com/en-us/azure/durable-task/common/durable-task-orchestrations

- **SMB Azure file shares**

  Added steps to disable SMB 1 on Linux clients accessing Azure Files, including checking kernel support, reloading the cifs module with disable_legacy_dialects, persisting the setting, and verifying the effective parameter. This strengthens guidance for secure SMB usage.

  https://learn.microsoft.com/en-us/azure/storage/files/files-smb-protocol

- **Silently install the Azure File Sync agent**

  Reorganized content to separate default and custom silent install workflows and added clear scenarios for automation use. Introduced updated command examples, documented parameters and behaviors (/qb vs /qn), corrected ENABLE_AGENT_AUTO_UPDATE values, and provided an unattend file example.

  https://learn.microsoft.com/en-us/azure/storage/file-sync/file-sync-agent-silent-installation

- **Replace a Drive on an Azure File Sync Server**

  Clarified operational steps, including ensuring the Storage Sync Agent Service is started before deleting server endpoints and temporarily disabling the agent before the final Robocopy pass. Added a cleanup phase to remove temporary endpoints, unregister the temp server, decommission it, and set volume free space policy.

  https://learn.microsoft.com/en-us/azure/storage/file-sync/file-sync-replace-drive

- **Recover an Azure File Sync server**

  Refocused on disaster recovery after server failure with guidance to set up a replacement server and re-sync from the cloud. Clarified use of Initial Download Mode with cloud tiering, discouraged manual copies during namespace sync, and provided a Robocopy path for data not uploaded pre-failure, with cautions on concurrent recoveries.

  https://learn.microsoft.com/en-us/azure/storage/file-sync/file-sync-server-recovery

- **Configure ExpressRoute and Site-to-Site coexisting connections using the Azure portal**

  Updated supported gateway SKUs for coexistence, removing Standard and HighPerformance and limiting support to VpnGw1, VpnGw2, and VpnGw3. Other prerequisites remain unchanged.

  https://learn.microsoft.com/en-us/azure/expressroute/how-to-configure-coexisting-gateway-portal

- **Configure secure networking for a Microsoft Discovery Supercomputer**

  Updated outboundType terminology from UserDefinedNetworking to UserDefinedRouting across headings, text, and requirements. Clarifies routing via user-defined routing on the nodepool subnet and reiterates the need for a route table and managementSubnetId.

  https://learn.microsoft.com/en-us/azure/microsoft-discovery/how-to-configure-supercomputer-network-security

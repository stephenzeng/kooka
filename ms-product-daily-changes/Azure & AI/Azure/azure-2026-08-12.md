## New Articles

- **Azure CycleCloud version 8.9.2**

  Introduced release notes for CycleCloud 8.9.2 with new features such as proxy connection status on the cluster page and support for the Azure Bleu provider. Documented numerous fixes across CLI install, interactive account creation, UI stability and performance, cluster-edit behaviors, session reauthentication, Lustre mounting post-upgrade, LSF image/package issues, monitoring query accuracy, and Windows node bootstrapping behind restricted egress. Announced deprecation of the Basic public IP SKU and included multiple security fixes, resolving CVEs CVE-2026-65806 and CVE-2026-70340.

  https://learn.microsoft.com/en-us/azure/cyclecloud/release-notes/8-9-2?view=cyclecloud-8

- **Azure Batch special task event**

  Added a new event reference for job preparation, job release, and start tasks when they complete or fail. The page details the schema, including executionInfo and schedulingError fields, and provides a full example payload. It notes current limitations where retryCount and requeueCount are not populated.

  https://learn.microsoft.com/en-us/azure/batch/batch-special-task-event

- **Azure Batch task requeue event**

  Introduced event documentation for when tasks are requeued due to conditions like node removal, job disablement, or service recovery. The article explains relationships to subsequent task start events, includes a complete example, and defines executionInfo with requeue and retry counts as well as detailed errors. This helps operators diagnose and react to requeue scenarios more effectively.

  https://learn.microsoft.com/en-us/azure/batch/batch-task-requeue-event

- **Configure IPv6 Layer 3 forwarding in Azure VMware Solution**

  Added guidance for enabling IPv6 L3 routing between NSX segments, which is off by default and requires a Microsoft support request. The capability applies within a private cloud only; external connectivity requires alternatives such as a policy-based IPv6-to-IPv4 VPN via an NSX Tier-1 VPN. The article outlines scope, prerequisites, and links to Broadcom NSX documentation for configuration details and notes limited HCX support for IPv6 workloads.

  https://learn.microsoft.com/en-us/azure/azure-vmware/configure-ipv6-layer-3-forwarding

- **Create MCP Connectors for Agents and Azure Integration**

  Introduced a how-to for creating MCP server connectors (Managed and Configurable) within a Connector Namespace. It covers prerequisites, current limitations, and step-by-step setup, including filtering tools, assigning input providers, and testing in the built-in playground. This enables agents and Azure integrations to securely invoke MCP-hosted actions.

  https://learn.microsoft.com/en-us/azure/connector-namespace/create-mcp-server-connectors

- **Migrate an Azure Stream Analytics Job Between Regions**

  Added end-to-end migration guidance for moving Stream Analytics jobs across regions. The article spans prerequisite roles, dependency inventory, downtime planning, exporting and compiling to ARM templates, parameterizing for a new region, deployment paths, and validation before cutover. It also includes rollback steps, checkpoint and data replay considerations, post-migration verification, and cleanup.

  https://learn.microsoft.com/en-us/azure/stream-analytics/move-across-regions

- **Mutual TLS authentication (Preview)**

  Introduced mTLS for Azure Front Door Premium (preview), including validation modes, certificate checks, SAN/CN allow-listing, and OCSP revocation. The guidance covers design considerations (no caching with mTLS, endpoint/domain scoping, Key Vault management, CA size limits), exposed metrics, quotas, and step-by-step portal configuration. A troubleshooting matrix decodes mTLS-related 403 errors using X-Azure-DebugInfo to speed resolution.

  https://learn.microsoft.com/en-us/azure/frontdoor/mutual-tls

- **Batch Rule Updates for Rule Sets**

  Added a concept for batch rule updates in Azure Front Door Standard/Premium, enabling atomic application of all rule changes. Explains the difference between Classic and Batch modes, immutability of the chosen mode, and when to use each approach (e.g., frequent reordering or IaC-driven management). Details quota implications—such as caching-enabled rules counting as two—and best practices to avoid temporary quota breaches during updates.

  https://learn.microsoft.com/en-us/azure/frontdoor/rule-set-batch

- **Create a Virtual Network Flow Log by Using Terraform**

  Published a Terraform-based how-to for creating Network Watcher VNet flow logs, including required resources, sample files, variables, and apply/verify steps. It explains outputs, cleanup, and common troubleshooting guidance. This accelerates IaC adoption for network observability.

  https://learn.microsoft.com/en-us/azure/network-watcher/vnet-flow-logs-terraform

# Azure
**Date created:** 2026-08-02 UTC  
**Tags:** Administration, Monitoring, Security  

## New Articles

- **Cross-Origin Resource Sharing (CORS)**

  Introduced a concept article for Azure Front Door Standard/Premium that explains how CORS works, including simple and preflight requests. Provides guidance for wildcard and single-origin configurations, highlighting caching implications and when to purge if headers change. Shows how to handle multiple origins using rules sets to dynamically set Access-Control-Allow-Origin and related headers. Includes references to the rules engine, external CORS guidance, and next steps.

  https://learn.microsoft.com/en-us/azure/frontdoor/cross-origin-resource-sharing

## Major Changes

- **What is Azure Compute Fleet? **

  Expanded and clarified quota guidance without changing underlying Azure quotas. Increased the limit to 5,000 fleets per subscription per region and clarified per‑fleet target capacity up to 10,000 VMs or 100,000 vCPUs, with a single fleet spanning up to three regions. Replaced the quota table with a concise list and added guidance on how quotas apply to Compute Fleet usage.

  https://learn.microsoft.com/en-us/azure/azure-compute-fleet/overview

## Moderate Changes

- **Azure VPN Client prerequisites check for P2S VPN connections**

  Updated availability details for the Run Prerequisites Test feature, requiring Windows client version 4.0.0.0 or later. Documented history that the feature first shipped in 3.4.0.0, was rolled back, and reinstated in 4.0.0.0 to set clear version expectations.

  https://learn.microsoft.com/en-us/azure/vpn-gateway/azure-vpn-client-prerequisites-check

- **Create a VPN gateway using PowerShell**

  Clarified how public IP zones affect VPN gateway instance placement and resiliency. Explained zone-redundant behavior when all three zones are selected and that a Standard SKU public IP without a zone is zone-redundant in regions with availability zones. Added steps for single-zone deployments and references for deeper guidance.

  https://learn.microsoft.com/en-us/azure/vpn-gateway/create-gateway-powershell

- **DDoS Protection cost optimization principles**

  Refined recommendations for choosing DDoS Network Protection to emphasize fixed monthly pricing that covers up to 100 public IPs per tenant with lower per‑IP cost as usage grows. Encourages comparing pricing models by resource counts and highlights simplified operations through automatic protection for new resources.

  https://learn.microsoft.com/en-us/azure/ddos-protection/ddos-optimization-guide

- **Deploy a security partner provider**

  Updated Virtual WAN guidance to route Internet traffic through a trusted security partner and Private traffic through Azure Firewall. This reverses prior roles and simplifies applying the right controls per traffic type.

  https://learn.microsoft.com/en-us/azure/firewall-manager/deploy-trusted-security-partner

- **QuickStart: Create and configure Azure DDoS IP Protection using ARM template**

  Revised the template description to create a new resource group and a Standard SKU public IP with DDoS IP Protection enabled. Adjusted next steps to focus on telemetry for the protected public IP instead of a DDoS protection plan.

  https://learn.microsoft.com/en-us/azure/ddos-protection/manage-ddos-ip-protection-template

- **QuickStart: Create and configure Azure DDoS IP Protection using Azure PowerShell**

  Clarified cleanup by noting that deleting the resource group removes the public IP and all dependent resources. Updated references to direct users to telemetry for the protected public IP rather than a DDoS protection plan.

  https://learn.microsoft.com/en-us/azure/ddos-protection/manage-ddos-protection-powershell-ip

- **Secure traffic destined to private endpoints in Azure Virtual WAN**

  Updated FQDN-based rule guidance to set connected VNets’ custom DNS to the Azure Firewall private IP, configure the firewall policy’s custom DNS to the DNS forwarder VM IP, and require DNS proxy for FQDN filtering. Clarified that IP-based rules remain unchanged.

  https://learn.microsoft.com/en-us/azure/firewall-manager/private-link-inspection-secure-virtual-hub

- **Quickstart: Create an Azure Firewall and a firewall policy - ARM template**

  Updated the deployment description to reflect that the template now outputs a hub virtual network, an Azure Firewall, and a firewall policy with rule collection groups and IP groups plus supporting network infrastructure. Removed references to virtual WAN/virtual hub and sample virtual machines to align expectations with current outputs.

  https://learn.microsoft.com/en-us/azure/firewall-manager/quick-firewall-policy

- **Use Azure Firewall policy to define a rule hierarchy**

  Clarified that rule collections inherited from a base policy take precedence over child policy collections when they are the same rule type. Also specified that network rule collections are processed before application rule collections, regardless of inheritance.

  https://learn.microsoft.com/en-us/azure/firewall-manager/rule-hierarchy

- **Secure your Azure DDoS Protection deployment**

  Shifted guidance from enabling protection at the virtual network level to ensuring every supported public IP resource is covered. Clarified actions for both tiers: associate a DDoS protection plan with VNets for Network Protection and enable IP Protection on each public IP, with a quickstart for PowerShell configuration.

  https://learn.microsoft.com/en-us/azure/ddos-protection/secure-ddos-protection

- **Troubleshoot API server and etcd problems in AKS**

  Added troubleshooting steps to detect API server throttling (HTTP 429) and pinpoint high-volume API clients. Included Log Analytics Kusto queries to identify top callers and isolate those receiving 429 responses to speed root-cause analysis.

  https://learn.microsoft.com/en-us/troubleshoot/azure/azure-kubernetes/create-upgrade-delete/troubleshoot-apiserver-etcd

- **Types of attacks Azure DDoS Protection mitigates**

  Clarified that Azure DDoS Protection mitigates Layer 3 and Layer 4 attacks. Noted that Layer 7 attacks require a web application firewall used alongside DDoS Protection.

  https://learn.microsoft.com/en-us/azure/ddos-protection/types-of-attacks

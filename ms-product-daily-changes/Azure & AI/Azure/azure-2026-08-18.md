## New Articles

- **Portable VMware Cloud Foundation licensing reference for Azure VMware Solution**

  Introduced a comprehensive reference for portable VMware Cloud Foundation (VCF) licensing in Azure VMware Solution. It explains licensing timelines, per–private cloud scope, mixed BYOL/license-included scenarios, and host quota requirements. The article details how to calculate VCF cores per host type, when the VMware vDefend Firewall add-on requires additional licensing, and how keys are handled securely with monthly reporting to Broadcom. It also covers migrating legacy registrations to the Azure portal and includes a compliance checklist to help customers stay aligned with licensing obligations.

  https://learn.microsoft.com/en-us/azure/azure-vmware/portable-vcf-licensing-reference

- **Shared responsibility model for Azure Enclave**

  New guidance clarifies which responsibilities are managed by the Azure Enclave platform (networking, policies, diagnostics, guardrails, maintenance mode enforcement) versus those owned by customers (RBAC, configuration choices, workload deployment and maintenance). It advises against modifying platform-managed resources to avoid configuration drift and directs exceptions through maintenance mode and support. The article helps organizations adopt secure, compliant operational practices by aligning actions to the correct owner and process.

  https://learn.microsoft.com/en-us/azure/enclave/shared-responsibility-model

## Major Changes

- **Configure local RBAC for FHIR**

  Deprecated the ability to assign access via Microsoft Entra security groups for local RBAC in Azure API for FHIR. Guidance now directs granting access to individual users or service principals only. This change reduces misconfiguration risks and clarifies the supported identity types for secure access control.

  https://learn.microsoft.com/en-us/azure/healthcare-apis/azure-api-for-fhir/configure-local-rbac

- **Migrate AWS Network Load Balancer to Azure**

  The migration guide was extensively expanded with clearer scope, prerequisites, and a structured capability mapping between AWS NLB and Azure Load Balancer. It adds detailed cutover, validation, rollback steps, and production considerations such as DNS TTLs and downtime planning. New troubleshooting guidance covers UDP health probing, Floating IP/DSR requirements, and probe IP allowances. These updates provide end-to-end operational procedures to reduce risk and accelerate real-world migrations.

  https://learn.microsoft.com/en-us/azure/load-balancer/network-load-balancing-aws-to-azure-how-to

- **Release notes 2026: Azure Health Data Services**

  Added security hardening (stricter SMART on FHIR scope validation) and reliability improvements such as null-safety checks and reindex job robustness. Multiple bug fixes address bulk delete date filtering, bundle processing race conditions, search parameter deletion in sequential transaction bundles, retention of search parameters on deleted resources, and validation ordering for convert-data. Also announced removal of Microsoft Entra security group support for local RBAC Allowed object IDs in Azure API for FHIR. These updates improve security posture, data integrity, and operational reliability across services.

  https://learn.microsoft.com/en-us/azure/healthcare-apis/release-notes-2026

- **Snapshots and state management for Azure Container Apps Sandboxes (preview)**

  The sandbox state model was simplified by replacing multiple paused states with a single Stopped state and refining the Running definition. Snapshot guidance was clarified to emphasize immutable, point-in-time captures that must be replaced rather than modified. Section names were updated to better reflect behavior (Automatic vs. Manual). These changes make lifecycle and recovery behaviors easier to understand and operate.

  https://learn.microsoft.com/en-us/azure/container-apps/sandboxes-snapshots-state-management

- **Configure portable VMware Cloud Foundation for Azure VMware Solution**

  The article was rewritten to focus on configuring and managing BYOL per private cloud in the Azure portal, including enabling during creation and converting existing clouds without downtime. It adds steps for exchanging license-included reservations, separately registering the VMware vDefend Firewall add-on, updating/cleaning up registrations, and resolving failures. Licensing rules and core calculations are consolidated into a separate reference. This aligns guidance with the new operational model and simplifies ongoing license compliance.

  https://learn.microsoft.com/en-us/azure/azure-vmware/vmware-cloud-foundations-license-portability

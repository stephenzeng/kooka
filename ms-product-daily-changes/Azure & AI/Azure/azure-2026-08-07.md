# Azure
**Change date:** 2026-08-07 UTC  
**Tags:** Administration, Analytics, Automation, Governance, Other, Programming, Security  

## New Articles

- **Details of the policy enrollment structure**

  Introduced the Azure Policy enrollment structure (Preview) with concepts and JSON examples for creating enrollments tied to the Enroll enforcement mode. Documented required fields, supported resource selectors and inclusion/exclusion logic, and how to manage enrollments via Azure CLI, ARM/Bicep, and Terraform. Clarified update constraints (only assignmentScopeValidation and resourceSelectors via PATCH), deletion behavior, and listing enrollments at scope using atScope() and atExactScope() filters. This guidance helps govern where policy applies before enforcement, improving safe rollout and control.

  https://learn.microsoft.com/en-us/azure/governance/policy/concepts/enrollment-structure

- **Troubleshoot Azure Managed Lustre CSI Driver extension errors**

  Added a comprehensive troubleshooting guide for the Azure Managed Lustre CSI Driver extension on AKS. It covers diagnosing install issues, resolving region availability errors, and fixing controller/node pod failures, PVC Pending states, and node mount problems. Guidance includes required PV attributes, network and OS prerequisites, RBAC checks, and handling conflicts with prior non-extension installs. It also explains why node pods may be missing on unsupported node pools and how to schedule workloads to supported nodes.

  https://learn.microsoft.com/en-us/troubleshoot/azure/azure-kubernetes/extensions/troubleshoot-azurelustre-csi-extension-errors

## Major Changes

- **Details of the policy assignment structure**

  Expanded policy assignment guidance with clearer resource selector usage, including narrowing scope for enrollments alongside exemptions. Introduced the new Enroll enforcement mode with behavior details and when to use Default, DoNotEnforce, or Enroll, plus a scenario-to-mode selection table. Clarified defaults, remediation behavior, and linked to enrollment structure and related enforcement details to support safer policy rollouts.

  https://learn.microsoft.com/en-us/azure/governance/policy/concepts/assignment-structure

- **Deploy an update by using Azure Device Update for IoT Hub | Microsoft Doc**

  Announced migration to Device Update data plane API version 2026-06-01 and retirement dates for older versions. Introduced a new Download security setting in deployments with HTTPS (default) or HTTP, and documented the corresponding Azure CLI parameter (--download-security) and example usage. Noted that the selected downloadSecurity value appears in deployment details and cannot be changed after creation, and improved structure and clarity across portal and CLI guidance.

  https://learn.microsoft.com/en-us/azure/iot-hub-device-update/deploy-update

- **Understand download security (TLS) for Device Update for IoT Hub**

  Rewrote and expanded download security guidance to document the new deployment setting selecting HTTPS (TLS) or HTTP and the default behavior with API version 2026-06-01. Added decision guidance for choosing HTTP vs HTTPS, device readiness requirements, and steps for constrained devices (including FreeRTOS updates and URL parsing). Updated certificate and TLS guidance, including required trusted roots and supported versions/cipher suites, to help ensure secure content delivery.

  https://learn.microsoft.com/en-us/azure/iot-hub-device-update/device-update-tls-download

- **Configure zone redundancy for Azure Functions**

  Substantially expanded and reorganized instructions by hosting plan. Added explicit support/limitations by plan, steps to view supported regions, and end-to-end creation guidance for Flex Consumption and Premium via portal, CLI, Bicep, and ARM. Clarified Premium capacity and always-ready instance requirements, provided procedures to enable zone redundancy on existing plans (including storage prerequisites), and added verification and troubleshooting steps.

  https://learn.microsoft.com/en-us/azure/azure-functions/functions-zone-redundancy

- **Introduction to Azure security**

  Clarified VM disk encryption by noting managed disks are encrypted at rest by default and positioning Encryption at host as an optional setting that extends protection to temporary disks, caches, and host-to-storage flows. Added guidance on supported VM sizes, and on using platform-managed or customer-managed keys. Updated identity guidance by replacing “Password policy enforcement” with “Password protection,” emphasizing blocking weak passwords, MFA, account lockout, and risk-based controls. Included current recommendations to avoid routine password expiration for cloud-only accounts and to require password changes when compromise is suspected or confirmed.

  https://learn.microsoft.com/en-us/azure/security/fundamentals/overview

## Moderate Changes

- **Authorize access to APIs in your API center**

  Strengthened security guidance for API authorization scenarios in Azure API Center. Added cautions against using client credentials flow in the developer portal test console, recommended OAuth 2.0 authorization code with PKCE, and noted that API keys and OAuth secrets don’t work when anonymous access is enabled. Clarified that Key Vault access should use the API center’s managed identity.

  https://learn.microsoft.com/en-us/azure/api-center/authorize-api-access

- **Create a global load balancer with cross-subscription backends**

  Corrected and clarified PowerShell and Azure CLI steps for configuring global load balancers with cross-subscription backends. Fixes include proper retrieval of frontend IP configuration, correct parameter usage and variable references, subscription context for global resources, and the specific az command for adding backend addresses. Also standardized command flags and refined guidance on resource placement and SKU.

  https://learn.microsoft.com/en-us/azure/load-balancer/cross-subscription-how-to-global-backend
